## Retained reconstruction

The initial current-main object had 1/35 strict instruction matches. Correcting
the compiler context on unchanged source produced 13 strict and 18 data
matches. Recovery then corrected confetti lifetimes, board RNG/trigonometric
calls, packed colors, display-list allocation and quad loops, particle sorting,
renderer state and animation indexing, and particle-manager spawn/update logic.
The target calls `mbRandMod`, `mbSinDeg`, and `mbCosDeg`; these are intentional
semantic corrections from the previous `frandmod`/HuSin/HuCos approximation,
not claims that the two APIs are interchangeable.

ParMan's nested pause topology, zero-vector handling, unsigned random domains,
cast-before-multiplication timing domain, and double-literal arithmetic were
reconstructed from the target. Those choices differ observably from the old
approximation for fractional inputs; the matching instruction/call proof, not
an assumption that all inputs are integral, supports them.

### Native-code disclosure

Four small static kernels retain native paired-single arithmetic/copies with
readable scalar C fallbacks: four-vertex scale/translation, vertex clearing,
four UV-pair copy, and 12-byte Vec copy. Their scope is recorded in
`config/recovery/exceptions.json`. No gameplay decision, loop, branch, or sort
is implemented in assembly. They use actual typed buffer pointers, not numeric
stack slots. The clear/UV copy kernels disclose fixed FPR operands; this is a
native recovery exception under the user's standing approval, not C-only credit
or proof of original local names. Current calls use disjoint buffers. Partial
overlap and exceptional/fused floating-point equivalence of fallback code are
not asserted.

### Interface and caller preservation

Retail `mbParticleBlendModeSet` narrows an int argument to a stored byte;
retail `mbParManPosSet` narrows its int model ID at the Hu3D call. The canonical
header now matches those providers. Single's object is byte-identical across
the header change. SNPC needs the existing signed-int ID expression explicitly
narrowed back to `HU3D_MODELID` before the widened wrapper: the resulting SNPC
object is byte-identical to the old-header champion,
`8f9958a50d3f1243715e0d3961c1bff3d32a0aca43404dbe99752abc04fe8460`.
No incompatible prototype or non-prototype exception was used. The final
full-project source-selected build rechecks every affected Matching consumer.

### Source portability debt

The target insertion-sort pointer idiom decrements its cursor one element
before the array after shifting element zero, then stores through `moveP[1]`.
The target compiler emits the intended in-bounds access, but forming that
one-before pointer is not strictly conforming C pointer arithmetic. This is
explicit recovered source-shape portability debt, not proof of arbitrary
optimizer safety. Native-kernel fallback caveats above are separate.

## Reusable causal lessons

1. Correct compiler context before source tuning. Unchanged source closed 12
   instruction functions when scheduling/peephole context matched.
2. With operations, frame, loops, and calls closed, native candidate owner
   observations can distinguish persistent owners from phase-local owners.
   Draw's computed owner grouping removed 149 rows in one candidate; ParMan's
   parameter/counter grouping closed its remaining 49 rows in two retained
   changes. The trace shows candidate compiler identities, never target virtual
   IDs or the original source spelling.
3. The final sorter required a coupled source structure: a real inline entry-copy
   boundary and a distinct insertion phase's live variables. Moving a local
   alone was neutral; reusing the quicksort pivot regressed. Those failures did
   not exhaust the function or justify a syntax matrix. The coupled ordinary-C
   reconstruction closed all 16 remaining instruction rows.
4. Inspect native pointer operands before hard-coding homes. Named register
   pointer aliases folded into the correct stack-relative loads without
   address instructions. Numeric stack offsets and fake storage were unnecessary.
5. A target-correct public width can still perturb callers. The provider and
   caller must be checked together, with explicit truthful narrowing where the
   target retains it. A provider-only exact score is not a safe interface proof.

Existing compile/evaluate/retain, DTK/objdiff, and Win32 VarInfo/regalloc capture
tools supplied the necessary evidence; this owner did not require another
solver, dashboard, approval protocol, or an expanded probe matrix. Only compact
champion/trace constraints and final proof are useful durable evidence.
